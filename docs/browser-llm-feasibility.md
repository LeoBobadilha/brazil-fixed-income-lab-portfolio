# Browser LLM feasibility for the "Ask about this chart" panel

Status: **assessed, not adopted**. The site ships a curated question-and-answer
panel that works without any language model. This document records why a browser-based LLM is
not part of the default experience. It also sets the conditions under which one could be added
as an opt-in experiment.

## What the site does today

Every chart has an **Ask about this chart** button. The panel:

- offers suggested questions scoped to that chart (for example, the yield-curve chart suggests
  "What does this yield curve mean?");
- answers free-text questions by keyword matching against about 28 curated entries in
  `web/src/content/knowledge.ts`;
- fills in numbers only from `facts`: values the page computes from the published snapshot and
  the current selection. If a fact is missing, the sentence that needs it is left out;
- says explicitly that the answers are curated and **not generated by AI**;
- declines questions it has no curated answer for, instead of guessing.

Unit tests (`web/src/content/knowledge.test.ts`) check that every number in an answer comes from
the supplied facts or from fixed explanatory text, that scoping works, and that off-topic
questions are declined. Browser tests check the panel on desktop and mobile.

This meets the requirement that the Q&A must work without an LLM, and that no model may invent a
yield, duration, price change, tax amount or scenario result.

## Options assessed

| | WebLLM (MLC) | Transformers.js (ONNX Runtime Web) | Self-hosted inference server | Hosted API |
|---|---|---|---|---|
| Runs where | Visitor's browser, WebGPU | Visitor's browser, WebGPU or WASM | A privately run machine | Third-party cloud |
| Licence of runtime | Apache-2.0 | Apache-2.0 | Varies | Commercial |
| Works on a static GitHub Pages site | Yes | Yes | **No**: the site would depend on a privately run machine and expose a network endpoint | Needs a secret key: not possible on a static site without a proxy |
| Ruled out by the project constraints | No | No | **Yes** | **Yes** (no paid API) |

The two server options are excluded by the project rules:

- the public site must not depend on a privately run machine or network;
- no local inference endpoint may be exposed;
- no paid API may be integrated.

Only in-browser inference remains.

## In-browser inference: the facts

**Browser support (WebGPU), as of late 2026:**

- Chrome and Edge on desktop: since version 113.
- Chrome on Android: version 121 or later, on Android 12+ with Qualcomm or ARM GPUs.
- Safari 26: macOS, iOS and iPadOS 26.
- Firefox: Windows (141+) and Apple-silicon macOS (145+). Linux, Android and Intel macOS were
  still in progress.

Older phones, many Android devices, and visitors with hardware acceleration disabled get no
WebGPU at all.

**Download and memory.** Weights at 4-bit quantisation:

| Model class | Example | Download | GPU memory | Answer quality for this use |
|---|---|---|---|---|
| ~135M | SmolLM-135M | ~30 MB | small | Unusable for explanations |
| ~0.5B | Qwen2.5-0.5B-Instruct (Apache-2.0) | ~350–400 MB | ~0.4 GB | Fluent but unreliable on finance; frequent factual errors |
| ~1B | Llama 3.2 1B (Llama Community Licence) | ~700 MB | ~0.9 GB | Better phrasing, still invents details |
| ~3B | Llama 3.2 3B | ~1.8–2 GB | ~2.5 GB | Usable assistant, but too large to download on a phone or slow connection |

The runtime library adds several megabytes of JavaScript on top. A model must also be downloaded
once per browser profile before the first answer, and first-token latency on integrated GPUs runs
to several seconds.

**Accuracy risk.** Small models confidently produce wrong numbers and wrong rules: tax
brackets, custody rates, what "IPCA+" means. A model in this size range is not trained on
Brazilian Treasury data. At best it would receive the curated answer and the page facts in its
prompt (retrieval), and be asked to rephrase them. Even then it can alter numbers or add claims.

## Decision

1. **The default experience stays LLM-free.** The curated panel answers the questions the
   explanations are designed around. It is accurate by construction, adds no download, and works
   on every browser, including mobile and without WebGPU.
2. **No prototype ships.** Answer quality could not be evaluated on a fixed question set, and
   shipping an unevaluated model, even behind a flag, would put unverified financial text in front
   of visitors.
3. **Conditions for a future opt-in experiment:**
   - it is hidden behind an explicit flag (for example `?experimental-llm=1`) and a consent
     screen that states the download size before anything is fetched;
   - it never downloads on page load, and is lazy-loaded only after consent;
   - it runs only when WebGPU is available, and otherwise falls back to the curated panel;
   - the model only rephrases the curated answer for the question, given the page facts as
     structured input. It is told not to add numbers;
   - a post-check rejects any output containing a number that is not in `facts` or in the curated
     answer, and shows the curated answer instead. This is the same rule the current unit test
     enforces;
   - output is labelled "AI-rephrased, may contain errors; the curated answer is shown below",
     with the curated answer always visible;
   - it is evaluated first on a fixed question set covering every chart, with the pass rate
     recorded in this document. A model with Apache-2.0 or similarly permissive weights is
     preferred.
